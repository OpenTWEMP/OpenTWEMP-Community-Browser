# :bomb: OpenTWEMP Community Browser - Next Generation Edition

Данный документ содержит черновое описание *видения продукта (product vision)* для **версии следующего поколения** OpenTWEMP Community Browser.

---

## :star: Разработка современнего мультиплатформенного клиентского приложения

- [ ] Принять решение о модернизации классического графического интерфейса (миграция с Windows Forms на WPF/WinUI).
- [ ] Выбрать кросс-платформенный GUI-фреймворк (MAUI, Blazor Hybrid, WebView2, Avalonia UI, Uno Platform и т.д.).
- [ ] Реализовать базовые элементы управления GUI на основе существующего интерфейса классического приложения.
- [ ] Реализовать механизм изменения цветовой схемы в новом графическом интерфейсе на основе существующего кода.
- [ ] Реализовать механизм изменения языка локализации в новом графическом интерфейсе на основе существующего кода.
- [ ] Подготовить несколько различных виртуальных машин для тестирования обновленного графического интерфейса.

## :star: Подготовительные эксперименты по превращению программы в полноценный клиент

Ниже представлен ориентировочные экспериментальные задачи, связанные с превращением программы в клиентское приложение.

Данный список имеет смысл дополнить новыми идеями на более позднем этапе дальнейшего развития программы.

### :bulb: *Эксперимент: Локальная база данных приложения*

Попробовать сохранять наиболее важные пользовательские параметры в локальной базе данных (SQLite или NoSQL-решение).

### :bulb: *Эксперимент: Служба-работник приложения*

Попробовать задействовать экспериментальную службу-работник приложения (обдумать потенциальные варианты использования).

### :bulb: *Эксперимент: Удаленное хранилище мод-пресетов*

Попробовать реализовать загрузку отдельных (либо сразу всех) поддерживаемых мод-пресетов с удаленного сервера.

## :star: Автоматизация построения инсталляционных файлов программы

### :bulb: *Создать конвейер непрерывной интеграции на базе GitHub Actions*

- [ ] Автоматизировать запуск процесса построения приложения из исходного кода.
- [ ] Автоматизировать запуск процессов автоматизированного тестирования проекта.
- [ ] Автоматизировать процесс построения инсталляционных пакетов приложения.
- [ ] Автоматизировать процесс обработки результатов запуска CI/CD конвейера проекта.

### :bulb: *Определить конфигурацию развертывания программы*

- [ ] Определиться со списком поддерживаемых приложением целевых платформ и операционных систем.
- [ ] Принять решение о способе развертывания приложения на компьютере конечного пользователя.

Типичными конфигурациями развертывания могут быть Development (Debug/Release) и Production (Publish).

### :bulb: *Выбрать наиболее подходящий способ распространения программы*

- [ ] Принять решение о способе поставки артефактов приложения конечному пользователю в Интернете.
- [ ] Подготовить стандартную страницу релизов для размещения ссылок на скачивание данной программы.

Наиболее интересными вариантами поставки могут быть следующие:

- Создание всевозможных артефактов с помощью GitHub Actions
- Создание официальных установщиков MSI для программы
- Использование архиваторов штатными средствами командной строки
- Использование программ-инсталляторов (NSIS, Inno Setup и т.д.)
- Современные менеджеры пакетов (Chocolatey, WinGet и т.д.)
